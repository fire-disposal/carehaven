# HPS 方法与研究计划

> 状态：当前 HPS 是**原型参数**，未做测量学校准。本文记录公式、已知缺口、权重/阈值研究路线；代码事实以 `pb_hooks/lib/hps.js`、`pb_migrations/1730000100_seed_demo.js` 为准。

## 1. 当前实现

```
HPS = Σ(w_i · s_i) / Σw_i        （缺失分量按剩余权重归一）
```

| 分量 | 当前算法 | 默认参数 |
|---|---|---|
| 生理 `s_physio` | HRV 反向归一 + GSR 正向归一 + 睡眠质量反向归一的均值 | `hrv` 20–60 ms、`gsr` 2–8 µS、`sleep_quality` 40–90；权重 `w1=0.4` |
| 心理 `s_psycho` | 当日全部打卡的平均：`0.45·心情 + 0.35·焦虑 + 0.2·疲劳` | `w2=0.4` |
| 情境 `s_context` | `0.6·min(照护时长/16,1) + 0.25·min(干预次数/5,1) + 0.15·min(问答次数/5,1)` | `w3=0.2` |
| 分层 | `HPS < 40` 绿；`40 ≤ HPS < 70` 黄；`≥70` 红 | `t_green=40`、`t_red=70` |

参数在 `app_config` 的 `hps_weights`、`level_thresholds`、`physio_normal_range` 中；分量内权重与上限目前硬编码。

## 2. 已知测量学缺口

| 缺口 | 现状 | 后果 |
|---|---|---|
| 参数不可复现 | `stress_scores` 只存结果；`app_config` 改完即覆盖；同日 upsert | 历史分数无法重算，论文说不清用的是哪版权重 |
| 缺失当 0 | 缺生理时 `score_physio` 写 0；`context` 永远入模，无数据时=0 | 缺数据/无打卡可能得到绿色，出现假阴性 |
| 情境分内生 | 干预次数、问答次数越多，HPS 越高 | 与“压力”构念纠缠；形成“干预→HPS↑→再推荐干预”的反馈环 |
| 来源不可信 | `checkins`/`physio_records` 客户端可写 `source`/`date`；演示数据含 `simulated` | 无法区分设备/模拟/补录；研究样本可被污染 |
| 量表未锚定 | `assessments` 与 `stress_scores` 没有同日关联字段 | 无法做收敛效度、区分度、校准分析 |
| 日级快照 | 同一用户同一天只有一行，日内重算会覆盖 | 不能支持日内动态研究，也不能回放评分过程 |

## 3. 研究立场

HPS 是**形成性指标（formative index）**，不是反映性量表：

- 三个分量共同“构成”压力，不是同一潜在特质的三个题项；**不要**对分量算 Cronbach's α。
- 权重是**政策参数**（专家判断 + 价值取舍），不是能从 HPS 自身识别出来的因果效应。
- 效度只能靠外部锚定：ZBI-12、PHQ-9、GAD-7，以及后续干预使用、脱落、危机事件。
- 当前阶段不应做个性化权重或 ML 学习权重；样本量不够，容易过拟合。

## 4. 权重与阈值计划

| 轨道 | 方法 | 产出 | 注意 |
|---|---|---|---|
| 专家赋权 | Delphi 2 轮 + 常和分配（100 分给 3 个分量）；需要正式一致性时再上 AHP | 权重中位数/四分位、理由、分歧记录 | 8–12 人：老年精神科/神经内科、精神科护理、社工、照护者代表、方法学 |
| 阈值锚定 | 标准化情景案例让专家判绿/黄/红；或用 PHQ-9≥10、GAD-7≥10、ZBI 高负担做 ROC | 阈值及置信区间 | 40/70 是默认值，不能直接当临床依据 |
| 实证校准 | 固定锚点后，在单纯形上做 0.05 步长网格（约 231 组），嵌套交叉验证比较 AUC/Brier/校准斜率；one-SE 规则选最简权重 | 候选权重集、与专家权重的差异 | n<100 不拟合；不要在同一批数据上既选权重又报性能 |
| 敏感性分析 | 对专家权重分布做 Monte Carlo，对用户做 bootstrap | 分层改变比例 | 若 >20% 用户因合理波动换层，先不要上线动态调权 |

**决策规则预先写死**：默认采用专家权重；只有当实证权重在预注册主指标上超过预设幅度、且分层稳定性 ≥80% 时才替换；否则保留专家权重并如实报告。

## 5. 研究阶段

| 阶段 | 周期 | 做什么 | 样本 | 产出 |
|---|---|---|---|---|
| 0 方法冻结 | 2 周 | 写清构念、分量、缺失规则、参数表 | — | 本文 v1 |
| 1 专家赋权 | 2–3 周 | Delphi + 常和分配 + 阈值情景 | 8–12 专家 | 权重/阈值表 + 理由 |
| 2 可行性 pilot | 4–6 周 | EMA 依从、缺失、设备可行性、SUS | 30–50 照护者 | 依从率、缺失率、可用性 |
| 3 锚定验证 | 8–12 周 | 横断 + 纵向；HPS vs 三量表 | 100–150 | r/AUC/Brier/CI |
| 4 影子与决策 | 2 周 | 候选参数并行评分、稳定性 | 同上 | 采纳/不采纳报告 |
| 5 干预 pilot | 可选 | 分层干预 vs 常规/等待 | 60–80 | 可行性/效应量 |

样本量：r=0.3、α=.05、power=.8 约需 85 人；r=0.4 约 47 人。验证队列建议 ≥100；二分类锚点按 EPV≥10 估算。缺失数据报告每个分量的覆盖率，用多重插补/混合模型，**不要零填充**。

## 6. 技术前置

1. `stress_scores` 增加 `algorithm_version`、`params`、`coverage`、`quality`、`computed_at`；新增 append-only `stress_score_events`。
2. 抽出纯函数 `hps-core.js`，`hps.js` 只做查询/持久化；加 golden vectors 单测。
3. 缺失分量可空；无数据返回“数据不足”，不返回绿色。
4. 客户端写入收口到服务端；设备数据走独立入口 + token；研究视图排除 `simulated`/demo。
5. `app_config` 校验 Σw=1、0≤w≤1、阈值有序；增加 `app_config_history`。
6. 量表与 HPS 按用户+日期关联；研究导出带数据字典与 manifest。

详细后端工作见 [backend-roadmap.md](backend-roadmap.md)。

## 7. 红线

- `source="simulated"` 与 seed demo 数据只能用于链路/UI，**不能进入权重估计或论文结果**。
- `checkins.note`、社区内容、TTS 文本都可能含敏感信息；研究导出默认排除或单独同意后脱敏。
- HPS 不是诊断工具；对外文案用“综合压力指数/分层提示”，避免“诊断/治疗/实时监测”。
- 在 n<100 前不要宣称“机器学习动态权重”。

## 8. 验收

- 任一历史日期的 HPS 可由快照回放到同值。
- 无数据/缺分量不会得到绿色分层。
- 配置变更可追溯，非法权重被拒绝。
- 研究导出只含真实、已同意、去标识的数据。
- 预注册的主指标与敏感性分析结果可复现。
