# 项目路线图（2026-10）

> 入口文档：只列里程碑、依赖与验收；细节见各专题文档。

## 当前状态

- 原型链路已跑通：打卡/生理 → HPS → 分层干预 → 量表/问答/TTS；单机部署与备份已落地。
- 视觉基座已落地：「纸本 · 松烟」+ 组件基座，见 [design-direction.md](design-direction.md)。
- 未对外开放注册；UGC 仍在 `main`，AI 问答仍是检索式，HPS 未校准。

## 里程碑

| # | 里程碑 | 状态 | 内容 | 验收 |
|---|---|---|---|---|
| M1 | 视觉基座 | ✅ 2026-10 | 令牌、组件、首页/登录/减压/我的/关于、宽屏栏宽 | `typecheck` + H5 + weapp 构建通过；关键页实机检查 |
| M2 | 后端数据地基 | 进行中 | 写入收口、评分快照、配置治理、角色/审计、数据权利、限流、测试 | 见 [backend-roadmap.md](backend-roadmap.md) P0 |
| M3 | UGC 归档 | 待执行 | `archive/ugc` + tag；主线移除入口/路由/表 | 见 [ugc-archive.md](ugc-archive.md) |
| M4 | HPS 测量 pilot | 待启动 | 专家赋权、阈值锚定、30–50 人可行性 | 见 [hps-method.md](hps-method.md) 阶段 1–2 |
| M5 | 研究验证 | 待启动 | 100–150 人锚定 ZBI/PHQ/GAD；影子评分 | 预注册、r/AUC/CI、分层稳定性 |
| M6 | AI 问答/agent | 可选 | RAG 问答 → 只读工具 → 写工具（二次确认） | 见 [ai-agent.md](ai-agent.md) 分阶段 |
| M7 | 正式化/运营 | 待启动 | 主体/备案/隐私/UGC 边界/客服/监控/成本 | 见 README「边界」与 `wechat-onboarding.md` |

## 依赖

- M2 是 M4/M5/M6 的前置：没有可信写入、评分快照与研究导出，权重研究和 agent 评测都不成立。
- M3 可与 M2 并行；越早剥离，备案与类目越简单。
- M6 必须建立在 M2 的限流/审计与 M4 的安全话术之上；不要先接模型再补边界。
- M7 的前提是 M2 + M3；公开注册要等数据权利与审核能力就绪。

## 明确不做（当前阶段）

- 不换 Postgres、不拆微服务、不上多副本；SQLite + 单容器足够 pilot。
- 不做个性化/ML 权重；n<100 不拟合。
- 不做通用聊天助手；只做照护场景内的受控问答与工具调用。
- 不在没有评测与安全兜底时对外宣称“AI 诊断/治疗”。
