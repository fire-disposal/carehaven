# 项目路线图（2026-10）

> 入口文档：只列里程碑、依赖与验收；细节见各专题文档。

## 研究优先级（置顶，2026-11）

1. **数据卫生**：回放全绿、评估窗口可见可点、退出原因结构化。
2. **先验迁移**：文献先验 → pilot 贝叶斯更新，产出权重/阈值的区间而非点值。
3. **个体校准**：每人 5–10 个锚点，混合效应模型，标注 `calibration_version`。
4. **设备域校准**：设备到位后做 20–30 次同窗配对，再启用设备分。
5. **运营最小闭环**：参与者级依从、导出留痕、只读研究角色。

详见 [research/migration-learning.md](research/migration-learning.md) 与 [research/carehaven-transfer-learning.pdf](research/carehaven-transfer-learning.pdf)。

## 当前状态

- 原型链路已跑通：打卡/生理 → HPS → 分层干预 → 量表/问答/TTS；单机部署与备份已落地。
- 视觉基座已落地：「木质 · 淡叶」（M3 控件语言）+ 组件基座，见 [design-direction.md](design-direction.md)。
- 未对外开放注册；自由文本社群已下线，互助以词元拼句回归；AI 问答仍是检索式，HPS 未校准。

## 依赖

- M2 是 M4/M5/M6 的前置：没有可信写入、评分快照与研究导出，权重研究和 agent 评测都不成立。
- 可复现条件（事件表、评分版本、数据集 manifest、恢复演练）单列在 [platform.md](platform.md)；M4/M5 的结论只有在满足其 P1–P3 退出条件后才可写进材料。
- M3 可与 M2 并行；越早剥离，备案与类目越简单。
- M6 必须建立在 M2 的限流/审计与 M4 的安全话术之上；不要先接模型再补边界。
- M7 的前提是 M2 + M3；公开注册要等数据权利与审核能力就绪。

## 明确不做（当前阶段）

- 不换 Postgres、不拆微服务、不上多副本；SQLite + 单容器足够 pilot。
- 不做个性化/ML 权重；n<100 不拟合。
- 不做通用聊天助手；只做照护场景内的受控问答与工具调用。
- 不在没有评测与安全兜底时对外宣称“AI 诊断/治疗”。
