# 结构化互助（UGC 的受控回归）

> 状态：**已实现并跑通**（2026-11）。取代原「UGC 归档与主线剥离」方案：自由文本社群仍不上线，
> 但互助以「词元拼句」的形式回到主线。旧表 `posts` / `comments` 保留数据、关闭全部 API 规则。

## 1. 决策

| 形态 | 结论 | 原因 |
|---|---|---|
| 自由文本发帖/评论 | ❌ 不恢复 | 审核、举报处置、社区类目、敏感信息留存四件事都要配套，原型阶段撑不住 |
| 词元拼句 + 固定回应 | ✅ 已上线 | 句子由平台词库生成，用户只做**选择**；表达空间足够，文本风险归零 |

一句话：**表达的自由度收窄到「组合」，治理的对象从「内容」变成「词库和组合」。**

## 2. 为什么这仍然是 UGC，但义务轻得多

- 用户不创作句子：`text` 由 `pb_hooks/lib/lexicon.js` 按固定模板拼接，客户端提交的只有槽位词元 id。
- 不提供任何输入框：社区页全页无 `textarea` / 文本 `input`（实测：仅剩匿名开关的 checkbox）。
- 回应是固定四选一（我也是 / 抱抱 / 有用 / 加油），一人一帖一条，重复提交即改选；评论能力随之取消。
- 组合仍有语义风险（例如拼出暗示第三方隐私或指责的句子），所以保留最小治理：举报 → 3 人自动隐藏 → 人工复核；每人每天 5 句上限。
- 词库是**发版内容**，不是后台可编辑数据：评审在 git 里完成，帖子记录 `lexicon_version`，语义可回溯。

对外文案必须与之一致：这是「从词库拼接的互助留言」，不是「用户可以自由发帖的社区」。

## 3. 词库与渲染

槽位 4 个，场景 8 × 感受 8 × 做法 8（可不选）× 想说 7 = **4032 种组合**；另有 6 组内置组合（`presets`），点一次即可成句，再按需微调。

```
{scene}，{feeling}。{tried}。{wish}。
夜里他又起来找门，我累得说不出话。我试着把走廊的灯留着。有人也是这样吗。
```

| 槽位 | 必选 | 说明 |
|---|---|---|
| `scene` 发生在什么时候 | 是 | 夜间游走、重复提问、认不出我、拒食、拒出门、发脾气、独自白天、终于睡着 |
| `feeling` 那一刻我是 | 是 | 累、怕、委屈、烦、空白、平静、撑不住、想有人替一晚 |
| `tried` 我试过的办法 | 否 | 留灯、写字沟通、陪着等、请人搭手、阳台十分钟、提前提醒、没找到办法、先不出声 |
| `wish` 我想对同路人说 | 是 | 有人也这样吗、怎么熬过去的、想听一句肯定、抱抱、留一口气、明天再试、只想被听见 |

内置组合（服务端 `lib/lexicon.js` 的 `PRESETS`）：夜间照护 / 白天独处 / 反复提问 / 认不出我 / 留一口气 / 明天再试。组合在模块加载时校验：词元必须存在、必选槽位齐全、能拼成句，否则服务端启动即报错。

渲染规则与粘合词写在 `lib/lexicon.js` 的 `RENDER` 里并由接口下发，客户端只用它做预览；
服务端是唯一真源。词元措辞必须自适配固定粘合词（逗号/句号），新增词元前先跑一遍组合。

## 4. 数据模型

| 集合 | 关键字段 | 规则 |
|---|---|---|
| `whispers` | user, nickname, kind(分享/求助/陪伴), text, terms(json), lexicon_version, anonymous, reactions_count, reaction_counts(json), report_count, hidden | 读：登录且（未隐藏或本人）；写：仅服务端路由；删：本人 |
| `whisper_reactions` | whisper, user, kind | 唯一索引 `(whisper, user)`；读：登录；写：仅路由；删：本人 |
| `whisper_reports` | whisper, user, reason(暴露隐私/攻击他人/不合适/其他) | 唯一索引 `(whisper, user)`；全部规则 `null`，仅管理员可见 |

索引：`whispers(created desc)`、`whispers(hidden, created desc)`。

## 5. 接口

| 接口 | 行为 |
|---|---|
| `GET /api/zz/whispers/lexicon` | 下发词库版本、槽位、渲染规则、回应与举报原因 |
| `POST /api/zz/whispers` | 校验 `kind` 与四个槽位词元 → 拼句 → 写库；超过每日上限返回 429 |
| `POST /api/zz/whispers/{id}/react` | 固定回应 upsert；计数以库重算，避免 JSON 自增漂移 |
| `POST /api/zz/whispers/{id}/report` | 举报去重；累计 3 人自动 `hidden=true` 等复核 |
| `GET /api/collections/whispers/records` | 信息流（按 kind 过滤） |

## 6. 旧自由文本表的处置

`pb_migrations/1730000500_whispers.js`：

- 新建三张表；
- 把 `posts` / `comments` 的 `list/view/create/update/delete` 规则全部置空（保留数据，可逆）；
- down 迁移删除新表并恢复旧规则。

因此 `/api/collections/posts/records` 与 `/api/collections/comments/records` 现返回 403，
`POST /api/zz/posts/{id}/like` 与评论计数 hooks 已从 `zhihu.pb.js` 移除（404）。

## 7. 未做与风险

- 举报处置**没有留痕台账**（谁在何时隐藏/恢复了哪条），补法见 [console.md](console.md)。
- 词库仍是代码，改词要发版；运营想即时改词只能等版本。这是有意的取舍。
- 组合语义巡检（例如「发脾气 + 指责他人」类）还没有自动化，只靠举报。
- 小程序类目：结构化留言通常不触发「论坛/社区」类目要求，但**申报时按实际形态描述**，不要写「社区发帖」。
- 旧 `posts` / `comments` 里的历史自由文本仍在库里：导出、保留期与删除请求要按原名单位处理。

## 8. 验收（已实测）

| 项 | 结果 |
|---|---|
| 合法组合落库 | 200，`text` 为服务端拼接结果 |
| 请求体自带 `text` 字段 | 被忽略，落库仍是拼接句（客户端无法注入正文） |
| 未知词元 `scene=hack` | 400「词元不在词库中」 |
| 每日第 6 句 | 429「今天已经拼了 5 句」 |
| 回应改选 | 计数不重复，`reaction_counts` 正确 |
| 第 3 个不同用户举报 | `hidden=true`，其他用户列表不可见，作者仍可见 |
| 匿名发布 | `nickname=匿名` |
| 旧自由文本表 | 登录用户 403；点赞路由 404 |
| 前端 | 社区页无输入框；拼句面板预览固定、操作条不被底部导航遮挡 |
