## 摘要

**范围**：在保持现有架构与成本可控的前提下，把迁移学习作为核心研究能力来建设：既支撑论文，也让 HPS 与照护负担评估具备可解释、可复现、可迁移的能力；同时改善数据收集体验与运营台可用性。

**结论先行**：

1. 迁移学习是本研究路线的核心能力：论文需要它，产品也需要它来解释「为什么一个新用户很快就能被理解」。
2. 迁移学习分五条并行轨道：**先验迁移、个体校准、设备域校准、表征迁移（含深度方法）、量表链接**。轻量轨道先交付，表征迁移同步准备。
3. 数据收集以「少打扰、按窗口、可核对」为原则；研究页直接给出下一次评估与一键进入，并围绕论文需要的锚点设计采集。
4. 组织路线与论文路线同步准备：角色、预注册、验证队列、可复现包与数据共享边界。

## 1. 现状审计（代码事实）

| 能力 | 现状 | 对研究的含义 |
|---|---|---|
| 评分 | `hps-3`；`stress_score_events` 追加写，含 `params`、`coverage`、`algorithm_version` | 历史分数可回放，满足可复现底线 |
| 缺失语义 | 缺指标不再补 0，`coverage` 标明缺失；无数据显示「数据不足」 | 降低假阴性；迁移模型按同一口径处理缺失 |
| 标签 | ZBI-12、PHQ-9、GAD-7；`assessments` 带 `date` | 可按「用户 + 日期」与 HPS 配对 |
| 生理 | 手动录入可用；BLE 与原生桥只有契约，无真实设备 | 设备域迁移暂无数据，只能先做配对采集设计 |
| 研究入组 | `studies` / `study_arms` / `study_enrollments` / `study_events`；按配比区组分配；评估窗口由 `schedule` 计算 | 已有分组与窗口，缺的是提醒与参与者级视图 |
| 数据导出 | `research/dataset.mjs`：HMAC 去标识 CSV + `quality.json` + `manifest.json`；排除未同意、演示账号、`simulated` 与自由文本 | 可直接作为迁移实验的输入，但需补「版本冻结」 |
| 回放 | `research/replay.mjs`：按事件快照与原始数据双重校验 | 迁移前后都必须过这一关 |
| 运营台 | `/admin/`：概览、研究按臂质量、举报处置、配置校验与历史、导出命令 | 够用；缺参与者级钻取与导出留痕 |

**结论**：数据地基已具备「可复现 + 可去标识」；下一步聚焦**配对样本与标签密度**，模型框架按现有架构演进。

## 2. 迁移学习怎么落到这个系统

### 2.1 五条并行轨道

| 轨道 | 迁移什么 | 数据需求 | 成本 | 论文价值 |
|---|---|---|---|---|
| 先验迁移 | 文献/公开队列的效应量 → 本系统参数先验 | 无需本地大样本 | 低 | 方法学与敏感性分析 |
| 个体校准 | 群体模型 → 个体截距与斜率 | 每人 5–10 次锚点 | 低 | 个性化与校准曲线 |
| 设备域校准 | 手动 ↔ 蓝牙/健康 App 读数映射 | 20–30 次同窗配对 | 低 | 测量一致性与域适应 |
| 表征迁移 | 公开生理/文本表征 → 冻结特征 + 线性头 | 有一定标签量与设备数据 | 中 | 迁移学习主结果、消融 |
| 量表链接 | ZBI-12 ↔ ZBI-22 等 | 双填或条目级数据 | 中 | 跨研究可比性 |

五条轨道共享同一份数据与评估协议；先交付前三条，表征迁移按实验计划推进。

### 2.2 先验迁移：把「权重研究」变成贝叶斯更新

- 目标：给 `hps_weights`、`level_thresholds` 设置**带不确定性的先验**，用证据替代固定值。
- 做法：文献给出心理/生理分量的合理区间 → 形成先验；pilot 的锚定数据更新后验；输出后验均值与 95% 区间，直接写进论文方法。
- 交付物：`research/priors.json`（来源、区间、理由）+ 一页敏感性分析。

### 2.3 个体校准：可解释的混合效应模型

```text
HPS_ij = β0 + β1·ZBI_ij + u0j + u1j·ZBI_ij + ε
u_j ~ N(0, Σ)  # 个体随机截距/斜率
```

- 群体部分从 pilot 估计；个体部分只需 5–10 个锚点即可收缩到稳定值。
- 新用户先走群体预测；锚点足够后再启用个体校准，并在 `stress_scores` 标注 `calibration_version`。
- 成本：统计脚本 + 导出字段，推理放在离线批处理。

### 2.4 设备域校准：配对测量是最便宜的办法

- 设计：要求设备用户每周做 1 次「手动 + 设备」同窗测量（相差 ≤10 分钟），形成配对样本。
- 模型：分指标的仿射映射（`y_manual = a·x_device + b`），带个体随机项；异常值用稳健回归。
- 验收：留一设备/留一用户交叉验证，MAE 与覆盖率同时报告；达到阈值后启用设备分。
- 工程接口：`physio` 接入层已区分 `manual / ble / app-bridge`；新增配对采集任务即可，HPS 保持不变。

### 2.5 量表链接：跨研究比较的关键一环

- 同一批人同时填长短版，或拿到条目级数据，用等百分位链接或 IRT 链接。
- 输出映射表 + 置信区间，冻结版本；采用等百分位或 IRT 测量学链接。

### 2.6 表征迁移与深度学习：核心方法，分步落地

迁移学习是论文的核心特性，深度表征同样在路线之内；重点是把方法做扎实、把验证做完整。

| 方法 | 适用场景 | 最低工程条件 | 交付 |
|---|---|---|---|
| 冻结特征 + 线性头 | 生理时序、文本检索 | 标签 ≥300 对；固定预处理 | 主结果 + 消融 |
| 轻量时序模型（TCN/GRU） | HRV/睡眠序列 | 设备数据连续、缺失可建模 | 对外部队列验证 |
| 表格基础模型/先验网络 | 小样本回归/分层 | 严格交叉验证、校准评估 | 与线性基线对比 |
| 文本表征迁移 | 知识检索、问答召回 | 中文 embedding、离线索引 | 不参与诊断输出 |

**数据与验证要求**：标签量与缺失率支撑交叉验证；用独立时间段或第二队列做外部验证；预注册主指标；模型卡记录训练数据版本与失败模式。

**工程形态**：离线训练（Python/Notebook），导出 ONNX/TFLite；推理放在服务端批处理。产物包括模型卡、数据 manifest、复现脚本与失败分析。

**组织准备**：数据管理员负责版本与脱敏；研究分析负责预注册与统计；工程负责训练/推理与回放；PI 负责临床解释与论文叙事。四条线并行，数据、模型与论文同步推进。

## 3. 科研检查清单（每次出数前必须过）

| 检查 | 判定 | 现有工具 |
|---|---|---|
| 同意与排除 | 仅纳入已同意、未撤回；排除演示与 `simulated` | `dataset.mjs` 默认规则 |
| 去标识 | HMAC 用户 ID；密钥由部署环境托管 | `RESEARCH_HMAC_SECRET` |
| 时间对齐 | 量表与 HPS 同日/同窗才配对；跨日不混 | `assessments.date` + 事件时间 |
| 缺失处理 | 按 `coverage` 分层或插补 | 评分快照 `coverage` |
| 可复现 | 任一历史分数可由快照与原始数据重算 | `replay.mjs` 双校验 |
| 版本 | 数据集带 `manifest.json`（时间、规则、数量、哈希） | `dataset.mjs` |
| 泄漏 | 训练/验证按用户或时间切分 | 实验脚本 |
| 预注册 | 主指标、样本量、敏感性分析先写后跑 | 研究方案 |

**验收底线**：回放一致（退出码 0）才进入建模与论文分析。

## 4. 数据收集体验：少打扰、按窗口、可核对

1. **研究页直接给下一步**：显示下一次评估窗口、量表清单、截止时间，并提供「去做第 N 天评估」按钮（本轮已在「我的 - 研究参与」加入）。窗口开放或过期都可一键进入，减少找不到入口造成的缺失。
2. **打卡一屏完成**：保持默认值预填、滑杆与数字键盘；备注与生理数据均为可选。
3. **配对测量任务**：设备接入后，按周生成一次「手动 + 设备」任务，完成即形成迁移样本。
4. **缺失可解释**：界面用「数据不足」标识；研究招募与知情同意中说明缺测不影响照护使用。
5. **退出必填原因**：退出研究时收集 1 个原因码（时间不够/不适/隐私/其他），用于流失分析。
6. **提醒**：围绕评估窗口发送一次提醒（站内 + 可选微信）。

## 5. 运营台（/admin/）使用检查与微调

**已合理**：概览、按臂质量、举报处置（必填理由）、配置校验与历史、导出命令、备份列表；写操作走服务端路由，保持单一权限来源。

**仍不合理/缺口**：

| 缺口 | 影响 | 低成本改法 |
|---|---|---|
| 只有按臂聚合，没有参与者列表 | 无法定位谁缺评估、谁该提醒 | 研究详情加「参与者」只读表（匿名 ID、入组日、打卡天数、评估次数、最近窗口状态） |
| 退出原因未结构化 | 流失分析只能靠猜 | 退出接口增加 `reason` 枚举与自由文本，写入 `study_events` |
| 导出命令靠复制 | 易漏参数、版本不可追溯 | 后台生成带时间戳的导出任务，记录操作者与 manifest 哈希 |
| 角色只有超管 | 导师/合作者只能给超管 | 增加只读研究角色（最小权限），写操作仍限超管 |
| 配置变更无差异视图 | 只能看历史值 | 历史行展示 before/after 与作者、理由 |

## 6. 置顶路线图（建议按此顺序）

| 优先级 | 事项 | 交付 | 验收 | 预估 |
|---|---|---|---|---|
| P0 | 数据卫生与研究页 CTA | 研究页下一次评估入口；退出原因；回放纳入 CI | 窗口可见可点；回放 0 退出码 | 3–5 天 |
| P1 | 先验迁移 | `priors.json` + 贝叶斯更新脚本 + 敏感性分析 | 后验区间可复现；专家签字 | 1–2 周 |
| P1 | 表征迁移基线 | 冻结特征 + 线性头 + 消融 | 与线性基线对比、校准指标 | 2–3 周 |
| P1 | 参与者级运营视图 | 研究详情参与者表 + 导出任务记录 | 一键定位缺测用户 | 3–5 天 |
| P2 | 个体校准 pilot | 混合效应模型 + `calibration_version` | LOSO 验证 MAE/校准斜率改善 | 2–3 周 |
| P2 | 设备配对采集 | 配对任务 + 仿射校准脚本 | 20–30 对样本，留一验证 | 设备到位后 2 周 |
| P2 | 深度时序/表格模型 | 轻量模型 + 外部验证 | 第二队列验证通过 | 4–6 周 |
| P3 | 量表链接 | 映射表 + 版本冻结 | 跨批次可比性报告 | 2 周 |
| P3 | 组织与论文包 | 预注册、SAP、模型卡、复现包 | 可提交的论文材料 | 持续 |

**成本口径**：一名工程师 + 一名研究分析，合计约 6–8 人周；沿用现有服务器与托管。

## 7. 工程接入点（保持现有架构）

- 导出：沿用 `research/dataset.mjs`；新增 `research/transfer/` 下的先验、校准、评估脚本，只读同一份 CSV + manifest。
- 评分：迁移结果以 `calibration_version`、`params` 写回 `stress_scores`，沿用事件追加，历史保留原版本。
- 设备：沿用 `lib/physio` 的 `source` 与 `ingestPhysio`；配对样本按普通采集写入。
- 运营：补只读聚合与导出记录，写入口保持在现有路由。

## 8. 组织与论文路线

| 角色 | 负责 | 产出 |
|---|---|---|
| PI / 临床 | 研究问题、量表选择、临床解释 | 预注册、论文叙事、伦理材料 |
| 研究分析 | 方案、统计、校准与外部验证 | SAP、分析代码、结果表 |
| 工程 | 采集、导出、训练/推理、回放 | 数据管道、模型服务、可复现包 |
| 数据管理员 | 同意、脱敏、版本、共享边界 | manifest、数据字典、访问记录 |

**论文路线（与产品并行）**：

1. 预注册：主问题（迁移是否改善校准/误差）、主指标、样本量、敏感性分析。
2. 数据冻结：manifest 哈希 + 回放全绿才进入分析。
3. 主分析：群体基线 vs 先验迁移 vs 个体校准 vs 表征迁移；报告 MAE、校准斜率/截距、Brier、分层稳定性。
4. 外部验证：第二队列或后一时间窗；失败也要报告。
5. 可复现包：数据字典、脚本、环境、模型卡；按同意范围共享。

**组织节奏**：每两周一次数据评审；每月一次论文/产品联合评审；所有变更写入研究事件与 manifest。

## 9. 执行与质量要求

- 纳入范围：已同意、未撤回、非演示账号、非 `simulated` 数据。
- 缺失处理：保留「未测到」语义，按 `coverage` 分层建模或插补。
- 特征口径：压力特征只保留心理、生理与生活负荷；干预与问答作为过程指标单独分析。
- 对外表述：以「群体先验 + 个体校准」描述能力，输出用于状态提示。
- 上线前：回放一致、预注册完成、模型卡与数据 manifest 归档。

> 一句话：数据可复现、标签按窗口、样本有配对，迁移学习就有了可靠起点。
