# EmoGuard 与智护忆站比对（2026-10）

## 结论

智护忆站不是把 EmoGuard 的页面换个皮，而是把它的方法学（EMA + 分层干预 + 知识支持）迁到更小的运维面（PocketBase 单二进制），并补上照护者场景特有的量表、朗读与正式产品入口。比对后已补齐：量表自评、语音朗读、意见反馈、关于、协议与隐私、数据来源说明、图标系统与趋势图交互。

## 技术栈

| 维度 | EmoGuard | 智护忆站 |
|---|---|---|
| 后端 | Django 5 + Django-Ninja | PocketBase（Go 单二进制 + SQLite） |
| 数据库 | PostgreSQL 15 | SQLite（数据目录即状态） |
| 队列 / 定时 | Redis + Celery + Beat | PocketBase cron（进程内） |
| 前端 | 微信原生小程序 | Taro 4 + React + TS（同时出 H5） |
| 鉴权 | JWT 双令牌 | PocketBase token + 微信 openid 绑定 |
| 部署 | 四容器 + Nginx | 单容器（H5 与 PB 同镜像） |
| 代码量 | 约 6000 行后端 | 表结构 + 迁移 + 少量 hook |

## UI 与设计取舍

### 1. 图标库取代 emoji

**问题**：emoji 在 iOS / Android / Windows 与不同微信版本里字形不一，同一「叶子」可能变成完全不同的颜色与比例；也无法跟随主题色。

**选择**：Font Awesome Free 7 Solid 子集（65 个字形），内联 base64 TTF，`Icon` 组件统一出口。

- 收益：跨端字形一致、可用 `color` 继承主题、尺寸统一、无需网络字体。
- 成本：字体子集体积约 17KB base64；图标库只有实心风格；许可需要署名（见 `icon-license.md`）。
- 保留 emoji 的地方：无。心情五档改为 `face-angry → face-grin-beam`，仍保留文字标签，不靠图标单独表意。

### 2. 一屏一个主行动

首页原来把「打卡入口」「生理面板」「压力卡」并列，主行动在折叠下方。现在压力卡底部直接放「记录此刻」，次级入口（量表 / 减压 / 问答）降为卡片行；打卡表单就地展开，不再跳页。

### 3. 对比度与字号

`$c-muted` 从 `#71868a`（白底 3.83:1）改为 `#5b7074`（5.23:1），主色从 `#2e8b84`（4.08:1）改为 `#287a73`（5.10:1），二级文字与主色文字达到 WCAG AA。正文仍保持 32rpx（16px）以上，关键数值 96rpx。

### 4. 趋势图减负

30 天柱状图原来每根柱子都标数值，横向滚动时信息噪声大。现在：

- 只标峰值、当前选中点与 7 天窗口的全部数值；
- 默认滚到最新一天，详情卡与选中柱一致；
- 7 天 / 30 天切换；
- 虚线表示窗口均值；
- 30 天每 5 天一个日期刻度。

### 5. 文案正式化

删除「内部原型环境」「项目组可见」「见 README」等面向开发者的提示；社区改为《用户协议》下的社区规范；关于页说明方法、数据来源与紧急支持。模拟数据仍明确标注，不伪装成设备采集。

## 仍需处理（按优先级）

1. **UGC 审核**：关键字过滤、举报队列、处置留痕；否则不开放注册与发帖。
2. **数据自助导出 / 删除**：目前政策写明通过反馈申请，尚未做界面。
3. **微信订阅提醒**：需要小程序订阅消息模板与用户授权，无法只靠前端完成。
4. **可导出报告**：把 30 天摘要生成 PDF / 图片；量表结果可附在报告里。
5. **键盘可访问性**：Taro `View` 在 H5 下仍不是原生按钮；如需 WCAG 全量合规，需要 H5 专用按钮或 `tabIndex` + 键盘事件封装。
